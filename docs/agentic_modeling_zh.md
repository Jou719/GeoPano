# GeoPano → Agentic Modeling：方案草案

## 目标

把 GeoPano 从“全景图 → 彩色点云”扩展成面向建模 agent 的**场景证据生成器**，再用一套可重复、可度量、可回滚的 harness，让 agent 以图像外观和几何证据为依据，逐步生成可交互的场景模型。

核心闭环是：

```text
全景图 → GeoPano 几何 → 结构化证据包 → agent 规划/编辑场景 → 渲染回全景视角
      ↑                                                          ↓
      └──────────── 误差分析、定向修正、停止条件 ─────────────────┘
```

目标产物不应只有一张三角网格：需要有可选择、可编辑的场景对象与材质，并能导出 `.blend`（继续编辑）和 `.glb`（浏览器/实时交互）。单张全景看不到的区域应标为先验补全或未知，不能伪装成观测事实。

可检验的核心假设是：带像素对应关系和置信度的几何证据，能让 agent 比“只看 RGB”或“只看点云”更准确地恢复房间结构；渲染—评分—编辑闭环能在固定调用预算内进一步改善误差，同时保持场景可编辑。结构保真、图像外观和对象可编辑性是不同目标，应分项验证。

## 现状与约束

- `files_inference.py` 已输出全景对齐的 `pano_points.npy`、径向深度、有效像素掩码和彩色 PLY。点图来自 10 个透视视图的预测与融合。
- 当前没有模型置信度、法线、曲率、结构线、室内 layout 或建模评估。深度和坐标也没有外部尺度校准，数值不能直接称为米。
- 融合函数当前返回的所谓 `pano_count` 实际是“至少有一个视图覆盖”的 0/1 掩码；它不是多视图观测数。置信度开发前需要保存真实视图贡献数，并衡量重叠视图点位的一致性。
- GeoPano 的点图、法线和曲率都是估计/派生信号。物体边缘、遮挡边界、反光表面及远处区域应允许低置信度或无效，避免 agent 把噪声硬拟合成几何。

## 系统分层

### 1. GeoPano 几何证据

保持现有推理模型不变，先在推理之后增加确定性的后处理，按“数值图 + 掩码 + 置信度”导出：

| 证据 | 建议表示 | 用途与注意事项 |
| --- | --- | --- |
| XYZ、径向深度 | float32 全景对齐数组 | 直接几何锚点；记录坐标系和无效值约定 |
| 视图贡献数、融合分歧 | uint8/float32 图 | 作为局部几何可信度线索；不能等同网络校准概率 |
| 法线 | float32 `[H,W,3]` + mask | 从局部点邻域稳健估计；跨全景水平接缝取邻居，极区/遮挡边界降低置信度；法线朝向相机并写明约定 |
| 曲率 | 主曲率或均值曲率 + mask | 在去噪/置信邻域上估计，供平面/边缘候选排序；不把高频噪声当细节 |
| 3D 直线/曲线候选 | 带支持像素、3D 采样点、类型、分数的 polyline | 从图像线段与 3D 点支持联合拟合；输出候选和残差，不声称每条都是结构线 |
| layout 候选 | 墙/地/顶平面、角点、墙地交线及支持区域 | 结合图像语义、法线/平面拟合和重力/曼哈顿先验；允许缺失和多解 |

工程顺序建议：先做法线和可信度；再做线/平面候选；最后做语义辅助的 layout。法线与曲率只是点图后处理，不能凭空带来新的观测信息；线与 layout 则要融合图像特征和几何，单靠 XYZ 通常不够稳定。

### 2. 证据包（agent 的输入契约）

每个场景一个不可变输入快照，避免 harness 内部临时文件和推理参数难以追溯：

```text
scene_bundle/
  panorama.png
  pano_points.npy
  pano_depth.npy
  pano_mask.png
  normals.npy                 # 后续阶段
  normal_confidence.npy       # 后续阶段
  curvature.npy              # 后续阶段
  primitives.json            # 线、曲线、平面、layout 候选
  semantics/                 # 可选语义 mask 与类别分数
  metadata.json
```

`metadata.json` 至少描述 schema 版本、输入哈希、全景尺寸、全景投影/朝向、坐标系（当前约定为 z-up）、尺度状态（当前为未校准）、GeoPano checkpoint 标识、有效掩码约定、派生算法版本和各属性的 confidence 语义。候选几何必须保留其支持像素范围，agent 才能把 3D 结构投回原图核验。

存储格式第一版优先简单可读：大数组用 `.npy`，结构化候选用 JSON，预览用 PNG。稳定后再按体积与随机访问需求决定是否迁移到 Zarr/Parquet 等格式。

### 3. 建模 agent 与工具接口

Agent 不应直接“写一大段 Blender 脚本然后猜结果”。Harness 给它一组有类型、有约束、可审计的动作：

1. `inspect_evidence(region | evidence_id)`：查询局部图像、点/深度/法线、候选结构及置信度。
2. `propose_scene_edit(...)`：声明要创建或修改的对象、参数、采用的证据 ID 和理由；低置信度证据不能自动变成硬约束。
3. `apply_scene_edit(...)`：在可回滚的 Blender 场景状态里执行受限操作，例如平面/盒体/挤出、对象实例、材质调整和局部网格修补。
4. `render_equirectangular()`：用原相机位置和投影渲染当前场景，保证可与输入全景对齐比较。
5. `score_scene()`：返回总分、分项分数、可信/不可信区域，以及最值得下一步处理的误差区域。
6. `checkpoint / rollback / export`：保留每轮场景、参数和评估结果，最终导出可编辑源文件及 GLB。

Agent 每轮只提交结构化场景编辑和证据引用；harness 负责参数校验、运行、渲染和评分。这样可以定位“模型哪里错了”以及“哪条证据导致了修改”。

## 监督与闭环评分

从当前全景相机位姿把场景渲染回 equirectangular 图像，建立多目标评分。几何尺度未标定时，对齐时只允许估计一个明确记录的全局尺度/刚体变换，不能通过局部自由形变掩盖结构错误。

- **外观**：有效且可见区域上的颜色/感知差异；球面全景按像素对应的球面面积加权，避免极区像素被过度计数。镜面、曝光和光照差异要单独处理。
- **几何**：渲染深度与 GeoPano 深度的稳健误差、点到面距离、法线夹角；权重按局部有效性和可信度调节。
- **结构**：平面、直线、曲线和 layout 的距离/角度/重投影误差，并按支持区域和候选分数加权。
- **正则项**：平面/墙体连贯性、网格质量、对象层级、几何复杂度和材质数；防止靠大量碎片过拟合单视角。
- **交互性**：GLB 可打开、对象可独立选择、层级与材质可读、面数/纹理预算、目标设备加载时间。

概念上可用下式聚合评分：

```text
E = λapp Eappearance
  + λgeo Σi ci ρ(Edepth,i + Epoint,i + Enormal,i)
  + λstruct Σj sj Eprimitive,j
  + λreg Ecomplexity
```

其中 `ci` 是几何证据的可靠度权重，`sj` 是结构候选的分数，`ρ` 为稳健误差函数；它们不是已校准的概率。权重需在带标注的验证集上定标，并报告每个分项，避免总分掩盖某一类失败。对外观误差还要屏蔽不可见/无效区域。

评估结果必须同时保留分项指标和误差热图。Agent 应优先修复“高置信度、显著且可解释”的误差；低置信度区域先询问/保留不确定性，而不是被总分强迫拟合。

单张全景只能约束可见表面和从其推断的室内结构。被家具遮挡或相机不可见的后侧不能由像素误差验证；应在资产中区分 `observed`、`inferred`、`unknown`，并通过对象元数据保留这种来源。绕场景预览可以检查几何是否破碎，但单张输入没有对应的新视角真值，因此新视角外观要作为先验质量/人工评估，不能报告成全景重投影精度。

## Harness 工程组成

```text
agentic_harness/
  bundle/       # 读取证据包、schema 校验、像素到 3D 坐标查询
  scene/        # Blender 场景创建、受限编辑工具、快照/回滚、GLB 导出
  render/       # 固定相机重渲染与可见性/遮挡处理
  metrics/      # 外观、几何、结构、复杂度和交互性指标
  agent/        # 模型适配器、工具定义、循环预算和停止条件
  eval/         # 数据清单、baseline、报告和可重复运行配置
```

一次运行要记录输入与模型哈希、代码版本、随机种子、Agent/工具调用、编辑 diff、每轮 render、分项指标、资源预算和最终资产。初期就应有失败样例归档，不能只保存最好看的结果。

## MVP 与验证路线

**MVP 0：几何证据包。** 固定一小批室内样例，导出真实视图计数、融合分歧、法线、法线可信度和统一 metadata；建立几何一致性检查及可视化。先不引入 LLM，也不扩展 GeoPano 网络训练。

**MVP 1：可控场景与闭环。** 做一个 Blender runner 和确定性基础建模器（房间平面/墙面/地顶/主要盒状物体），先证明重渲染与几何/外观评分可稳定工作；所有编辑可回滚。

**MVP 2：Agent 工具使用。** Agent 读取证据、提出带依据的 edit、调用渲染和评分，再根据误差热图修订。对照相同输入、相同迭代/模型预算下的“仅全景”、“全景+点图”和“全景+全证据”三组，验证物理属性是否真的提高结构与几何保真度。

**MVP 3：扩展属性与场景。** 加入线/曲线、语义和 layout 候选；逐步覆盖遮挡、低纹理、玻璃/镜面、开口和非曼哈顿房间等失败类型。

数据集至少要有成对全景、可渲染场景/网格、相机位姿和可用的深度/布局真值或标注。当前仓库的四张样例适合跑通界面，不足以证明几何精度或泛化；报告要区分数据来源、是否与训练场景重叠，以及真实标注覆盖范围。

## 首个工程里程碑的验收条件

1. 同一个输入快照可重复生成形状/坐标一致的证据包；所有数组有匹配尺寸、有限值和有效掩码。
2. 法线朝向约定、接缝邻域、无效点/深度边界都有自动检查和可视化。
3. 视图计数与融合分歧是实际统计量，confidence 字段明确说明不是校准概率。
4. 给定一个简单确定性房间场景，能生成全景渲染、分项评分、误差热图和可回滚记录。
5. `.blend` 与 `.glb` 均可重新打开；GLB 保留对象分组、材质和合理预算。

首阶段建议只做证据包 + 确定性 Blender 闭环。先验证“额外物理属性相对点云是否改善结构误差”，再把精力投入更复杂的 agent 与训练；这样能区分 GeoPano 属性的价值、Agent 的价值和建模先验的价值。
